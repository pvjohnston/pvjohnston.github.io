How the Hakyll build works

The notebook at pvjohnston.com is a static site. A post starts as Markdown in posts/. The Haskell program site writes HTML into _site/. GitHub Actions copies that directory to Pages. This page walks the code that does that, file by file. First pass against commit d3ba5c69.

02

Entry

main looks at one environment variable, then hands control to Hakyll. 

app/site.hsmain :: IO ()
main = do
  previewDrafts <- isJust <$> lookupEnv "PREVIEW_DRAFTS"
  hakyll (siteRules previewDrafts)

What this does

  1. hakyll is Hakyll’s CLI: build, rebuild, watch, clean.
  2. If PREVIEW_DRAFTS is set to anything, posts with YAML draft: true (that exact string) are built. CI does not set it. Otherwise they never enter the Hakyll store: no page, listing, feed, or sitemap row. draft: yes still publishes.
  3. All match/route/compile tables are siteRules in lib/Blog/Site.hs.

03

Rules

Hakyll is a dependency graph. Each match says: these files, this output path, this compiler. A post is one rule among several. Static pages (about, résumé, contact, colophon) use plain pandocCompiler. Posts use bibtexMathCompiler. 

lib/Blog/Site.hs    match (fromList staticPages) $ do
        route   $ setExtension "html"
        compile $ pandocCompiler
            >>= loadAndApplyTemplate "templates/default.html" baseCtx
            >>= relativizeUrls

    let publishable metadata = previewDrafts || not (isDraft metadata)
    matchMetadata "posts/*" publishable $ do
        route $ setExtension "html"
        compile $ bibtexMathCompiler cslFile bibFile
            >>= saveSnapshot "content"
            >>= loadAndApplyTemplate "templates/post.html"    postCtx
            >>= loadAndApplyTemplate "templates/default.html" postCtx
            >>= relativizeUrls

Markdown → HTML path

  1. setExtension "html" turns posts/2026-08-22-….md into _site/posts/2026-08-22-….html.
  2. The snapshot named content is the body after Pandoc, before the chrome templates. Atom/RSS take the last 20 of those bodies (the YAML description is overwritten). The home featured reel and hasFigure also read it.
  3. post.html wraps the article. default.html adds <html>, nav, footer, CSS, MathJax.
  4. relativizeUrls rewrites site-root links so a page still works if opened as a file.

Other rules in the same file, in order of appearance:

  • Load bib/style.csl and bib/bibliography.bib as Hakyll resources (citation compilers, not pages).
  • Copy images/*, js/*, fonts/*, downloads/*, LICENSE.
  • Compile research/*/metrics.json with metricsCompiler (parse or fail). Copy research/metrics.schema.json.
  • Copy every path listed in each experiment’s PUBLIC_FILES.txt, plus the manifest itself, except paths another rule already owns. A listed path that is missing is dropped here; verify-site.mjs is the gate.
  • Compress css/*.
  • Build tag pages for tags that appear on at least two posts (metadata scan includes drafts; the list on the page does not). Tag pages are not in the sitemap.
  • Build writing.html and archive.html as the same year-grouped listing.
  • Fill index.html with up to five figure-having posts in a reel and eight latest rows.
  • Write atom.xml, rss.xml, sitemap.xml (posts, index, writing/archive, static pages — not tags or 404).
  • Copy 404.html and robots.txt (after the sitemap rule).
  • Compile templates/* with templateCompiler.

04

The post compiler

bibtexMathCompiler is the only place a research note becomes HTML. The body of the function is one pipeline. 

lib/Blog/Compilers.hs  metrics <- loadPostMetrics

  getResourceBody
    >>= readPandocBiblio readerOptions csl bib
    >>= \pandoc -> do
          withMetrics <- walkM (metricFilter metrics) pandoc
          withTikz <- walkM tikzFilter withMetrics
          return $ writePandocWith writerOptions (walk wrapTables withTikz)

Order

  1. Read the Markdown, resolving [@citekey] against the CSL + BibTeX already loaded.
  2. Replace [name]{.metric} spans. A bad span fails the whole Hakyll build. A bad TikZ diagram does not.
  3. Replace fenced ```{.tikzpicture} blocks with inline SVG (or an error box). A \begin{tikzpicture} in prose is not compiled.
  4. Wrap tables in div.table-scroll.
  5. Write HTML with MathJax math and pygments highlighting.

Reader and writer options are not the same list. The reader starts from pandocExtensions and adds Ext_raw_html and Ext_raw_tex (off by default; needed so \ce{…} outside already-tokenized math can survive as TeX). The writer adds dollar math, double-backslash math, Ext_latex_macros, fenced code, and writerHTMLMathMethod = MathJax "". {.metric} is a reader bracketed span. Static pages never enter this function, so colophon and about have no citations, metrics, or TikZ. They still load MathJax in default.html.

05

Citations

Hakyll’s readPandocBiblio is Pandoc citeproc. The style is ACS (bib/style.csl). The database is bib/bibliography.bib, marked merge=union in .gitattributes so two branches can append keys. 

lib/Blog/Site.hscslFile, bibFile :: String
cslFile = "bib/style.csl"
bibFile = "bib/bibliography.bib"
…
    match (fromGlob cslFile) $ compile cslCompiler
    match (fromGlob bibFile) $ compile biblioCompiler

In the HTML

  1. In-text [@johnson2025] becomes a numbered citation. A missing key typically renders [?]; Hakyll does not fail.
  2. A heading ## References with no extra markup is filled by citeproc. The CSS targets #refs and .csl-entry.
  3. scripts/verify-bib.mjs runs first. It blocks new duplicate keys; a short grandfathered list is still allowed. It cannot catch one paper under two keys.

06

Math

Build time and browse time are split. Pandoc still has Ext_tex_math_dollars, so $…$ in a post becomes \(…\) in the HTML. The browser’s MathJax is configured with dollar delimiters off, so leftover $300K on a static page is not treated as math. 

js/mathjax-config.jswindow.MathJax = {
    tex: {
        inlineMath: [['\\\\(', '\\\\)']],
        displayMath: [['\\\\[', '\\\\]']],
        processEscapes: true,
        packages: {'[+]': ['base', 'ams', 'noerrors', 'noundefined', '[tex]/mhchem']},
        tags: 'ams'
    },
    loader: {
        load: ['[tex]/mhchem']
    }
};

Where it is loaded

  1. templates/default.html defers mathjax-config.js, then MathJax 3.2.2. The combined bundle has a Subresource Integrity hash. Extra MathJax files (including mhchem) do not.
  2. Display math scrolls horizontally (mjx-container in css/default.css).
  3. TikZ is not MathJax. Diagrams are already SVG before the page is served.

06 · chemistry

mhchem

Chemical formulas and equations use the mhchem command \ce{…}. MathJax does not know chemistry by itself. There are two engines. They can disagree. 

posts/2025-01-20-chemical-kinetics.markdown$$\ce{2H2O2 -> 2H2O + O2}$$

In a sentence

  1. Pandoc keeps this as math. The browser’s MathJax loads [tex]/mhchem via loader.load in js/mathjax-config.js.
  2. LuaLaTeX never sees this line.
lib/Blog/TikZ.hs  , "\\usepackage[version=4]{mhchem}"

In a figure

  1. A \ce{…} inside a ```{.tikzpicture} fence is compiled by LuaLaTeX with mhchem v4 and baked into the SVG.
  2. MathJax does not typeset that node.

07

TikZ

A fenced block tagged tikzpicture is compiled with LuaLaTeX and converted with dvisvgm --pdf --no-fonts. The SVG is inlined. Only that class hits tikzFilter. Posts with no such block never shell out, so a machine without TeX can still build the rest of the site. 

lib/Blog/TikZ.hstikzFilter :: Block -> Compiler Block
tikzFilter (CodeBlock (_, classes, _) contents)
  | "tikzpicture" `elem` classes = do
      result <- unsafeCompiler $ renderTikz (T.unpack contents)
      let html = case result of
            Right svg -> "<div class=\"tikz-figure\">" ++ inlineSvg svg ++ "</div>"
            Left err  -> "<div class=\"tikz-error\"><strong>Diagram failed to render.</strong>"
                          ++ "<pre>" ++ escapeHtml err ++ "</pre></div>"
      return $ RawBlock (Format "html") (T.pack html)
tikzFilter block = return block

Failure and cache

  1. A failed diagram does not abort Hakyll. It becomes .tikz-error and a line on stderr. verify-site.mjs later fails CI if the HTML contains the substring class="tikz-error".
  2. Only successful SVGs are cached, in _cache/tikz/, keyed by a hash of preamble plus source. Glyph ids use a hash of the source only. Local site clean deletes the cache. CI restores it after checkout.
  3. If the block already contains \begin{tikzpicture} or \begin{circuitikz}, it is used as-is. Otherwise the filter wraps a picture environment around the body. \standaloneenv{circuitikz} is why schematics crop.
lib/Blog/TikZ.hs  (texCode, texOut, texErr) <- readCreateProcessWithExitCode
    ( (proc "lualatex"
        ["-halt-on-error", "-interaction=nonstopmode", "-output-directory=" ++ dir, texFile])
        { cwd = Just dir }
    )
    ""
…
      (svgCode, svgOut, svgErr) <- readCreateProcessWithExitCode
        ( (proc "dvisvgm" ["--pdf", "--no-fonts", "--output=" ++ svgFile, pdfFile])
            { cwd = Just dir }
        )

Id collisions

  1. dvisvgm reuses glyph ids like g3-66 in every file.
  2. Inlining two SVGs on one page would mix glyphs. namespaceIds prefixes every id, href="#…", and url(#…) with a hash of that diagram.
  3. The unit tests in test/Spec.hs cover inlineSvg and namespaceIds.

The preamble loads tikz, pgfplots, amsmath, mhchem, and circuitikz. That is why chemistry schemes and circuit drawings can live in a Markdown fence.

08

Metrics

Three functions. metricsCompiler validates and publishes each research/*/metrics.json (a WIP file must not use that name). loadPostMetrics runs on every post with experiment:, even with no spans; a missing file fails Hakyll. metricFilter walks inlines. traceable in templates uses loadPostMetricsFor because inside a context field the underlying identifier is the page, not the post. 

lib/Blog/Metrics.hsloadPostMetricsFor :: Identifier -> Compiler (Maybe MetricsDocument)
loadPostMetricsFor post = do
  metadata <- getMetadata post
  case lookupString "experiment" metadata of
    Nothing -> pure Nothing
    Just rawSlug -> do
      …
      let metricsPath = "research/" ++ rawSlug ++ "/metrics.json"
      body <- loadBody (fromFilePath metricsPath)

In the page

  1. A span must be exactly [name]{.metric} with a name like [a-z][a-z0-9_]*. Extra classes fail the whole build. The output class is metric-value with data-metric.
  2. verify-site.mjs flags leftover class token metric (the unresolved form). Fixture pages that must match exact strings are the Brewster and microwave notes, not Hillel.
  3. Haskell does not re-run Psi4. Node’s verify-metrics.mjs checks hashes, path safety, and that generator --check does not rewrite the file.

09

Templates

Hakyll templates are HTML with $field$ holes. post.html is the article (tags, date, post-type, status, derived traceable, then $body$). default.html is the document. Script order: theme, topic filter, featured reel, figure cycler, MathJax config, code-copy, then MathJax. Share images are chosen in Blog.Context: YAML og-image, then images/<slug>-og.png if it exists, then the figure src, then the branded card. 

templates/post.html    <div class="post-body">
        $body$
    </div>

    <div class="post-foot">
        <a class="back-link" style="margin:0;" href="/writing.html">← All writing</a>
        <button type="button" class="print-link" onclick="window.print();">Print / Save as PDF</button>
    </div>

default.html

  1. Sets data-theme from localStorage or prefers-color-scheme before paint.
  2. Loads /css/site-theme.css then /css/default.css.
  3. Loads MathJax, theme toggle, topic filter, featured reel, figure cycler, code-copy.
  4. $body$ is the only main content. For a post, that body is already the rendered post.html.

Screen and mobile

Two stylesheets. site-theme.css is tokens, header, footer, drawer, buttons. default.css is the notebook: home, archive, article, about, résumé, colophon. Screen colors are CSS variables. One documented hex exception: TikZ sits on a constant light plate because the SVG ink does not flip with the theme.

@media (max-width: 680px) {
  .masthead-inner { padding: 48px 20px 40px; }

.table-scroll {
  overflow-x: auto; -webkit-overflow-scrolling: touch; margin: 0 0 24px;
  scrollbar-width: none; -ms-overflow-style: none;
}

What “mobile” is here

  1. Below 900px, site-theme.css hides the inline nav and shows the hamburger + drawer.
  2. Below 820px the home featured grid stacks. Below 680px article padding tightens.
  3. Wide tables scroll inside .table-scroll, which the compiler inserts. That is HTML+CSS, not a second layout engine.
  4. Code blocks scroll horizontally. MathJax display math does too.

Print

There is no PDF file. CI never writes one. The article is the same HTML. Posts have a window.print() button in post.html. The résumé has its own button in resume.markdown. The colophon has none (browser File → Print). Three @media print layouts live in css/default.css.

What changes on paper

  1. US Letter, 0.5 in margin. Saira and Barlow load with media="print". JetBrains Mono is a screen Google Font and is also the print --mono.
  2. Post print: hide nav/footer/buttons, cream code, square ticks on .post-body h2 (Saira/Barlow/Helvetica).
  3. Résumé print: Arial body, Saira title, hides .resume-print.
  4. Colophon print: restyles .method-*, keeps Bricolage, does not use the condensed post stack.

site-theme.css also has a short print rule: hide header/footer/theme toggle and force a white body. The article look is the longer block in default.css.

stack test

test/Spec.hs does not run Hakyll. It checks pure helpers: SVG inlining, id prefixing, table wrapping, metrics JSON parsing and formatting, og:image choice. CI runs it before site build.

13

verify-*.mjs

Three Node scripts. They are not Hakyll. They run in CI around the Haskell build.

  • verify-bib.mjs — duplicate citation keys on the source bib, before the expensive build. A grandfathered set is allowed. One paper under two keys is not caught.
  • verify-metrics.mjs — after site build in CI: hashes, experiment equals the directory name, path safety, 30s generator timeout, --check must not delete or rewrite the file.
  • verify-site.mjs — substring class="tikz-error"; leftover class token metric (not metric-value); internal href/src; each PUBLIC_FILES.txt path as a regular file in _site; og/twitter 1200×630 on pages with twitter:card; exact metric strings on posts/2026-07-20-from-script-to-sentence.html and the microwave-oven note.
scripts/verify-site.mjs  if (html.includes('class="tikz-error"')) {
    errors.push(`${label}: contains a failed TikZ diagram`);
  }

  const hasUnresolvedMetric = [...html.matchAll(/class="([^"]*)"/g)]
    .some((match) => match[1].split(/\s+/).includes('metric'));
  if (hasUnresolvedMetric) {
    errors.push(`${label}: contains an unresolved experiment metric`);
  }

Why this sits outside Haskell

  1. Hakyll can emit a TikZ error box and keep going. The Node check is the gate that refuses to publish it.
  2. Link checking walks the generated HTML, including relative URLs from relativizeUrls.

14

Deploy

One workflow: .github/workflows/deploy.yml. It runs on push to main, on pull requests to main, and on workflow_dispatch. Pull requests build and verify. Only non-PR runs upload Pages. 

.github/workflows/deploy.yml    - name: Build, test, and verify generated output
      run: |
        node scripts/verify-bib.mjs
        stack test
        stack exec site build
        node scripts/verify-metrics.mjs
        node scripts/verify-site.mjs

    - name: Add CNAME and .nojekyll
      if: github.event_name != 'pull_request'
      run: |
        echo "pvjohnston.com" > _site/CNAME
        touch _site/.nojekyll

Job shape

  1. build on ubuntu-latest, 60 minute timeout. Stack from haskell-actions/setup, GHC from the snapshot, not a second setup-installed compiler.
  2. Caches: Stack keyed on stack.yaml.lock + cabal; apt .debs; TikZ path _cache/tikz with Actions key including github.run_id (primary key never hits; restore-keys does). Files inside the TikZ cache are content-addressed.
  3. TeX: texlive-latex-extra, pictures, science, luatex, texlive-plain-generic, texlive-fonts-recommended, dvisvgm, mupdf-tools (mutool, dvisvgm’s PDF backend).
  4. The checkout has no Hakyll store, so site build is a clean site. The TikZ cache is restored after checkout (the opposite of local site clean).
.github/workflows/deploy.yml  deploy:
    if: github.event_name != 'pull_request'
    needs: build
    …
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
    steps:
    - name: Deploy to GitHub Pages
      id: deployment
      continue-on-error: true
      uses: actions/deploy-pages@v4

Pages

  1. Source is GitHub Actions, not a gh-pages branch. Comment in the file: force-pushing that branch was flaky.
  2. actions/upload-pages-artifact packs _site. actions/deploy-pages@v4 publishes it.
  3. Concurrency group pages, cancel-in-progress: false.
  4. If deploy fails, the workflow sleeps 30 seconds and retries once. Comment: the Pages backend has rejected a fresh artifact with no diagnostics; a rerun of the same tarball then succeeded.

15

Map · .md to HTML and print

One Markdown file does not have a single destination. Branches below are the ones in the compiler and CI. There is no generated PDF; print is the same HTML plus CSS.

runs exit / fail browser only

  1. Source

    posts/*.md or a static page (about.markdown, resume.markdown, contact.markdown, colophon.markdown).

  2. Exit · draft

    If YAML is exactly draft: true and PREVIEW_DRAFTS is unset, the file never enters the store. No HTML, listing, feed, or sitemap row. CI does not set the env.

  3. Branch · static page

    pandocCompiler → templates/default.html only. No citeproc, metrics, TikZ, or post.html. Still gets MathJax chrome. Résumé print CSS applies if you print that page.

  4. Branch · post

    bibtexMathCompiler, then snapshot, then two templates.

    • Citations: [@key] → numbered, or [?] if missing. Does not fail Hakyll. Duplicate keys: verify-bib.mjs first.
    • Metrics: YAML experiment: loads research/<slug>/metrics.json. Missing file or bad [name]{.metric} → Hakyll fail (whole build).
    • TikZ: class tikzpicture only → LuaLaTeX + mhchem v4 + dvisvgm → inline SVG. Failure → .tikz-error, Hakyll continues.
    • Math in prose: Pandoc emits \(…\) / \[…\] (including from $…$).
    • Chemistry in prose: \ce{…} stays TeX for the browser. Not LuaLaTeX.
    • Tables wrap in .table-scroll. pygments on code.

  5. _site HTML

    posts/….html plus copied images, CSS, JS, fonts, allowlisted research/ files, feeds, sitemap.

  6. Exit · CI after build

    verify-metrics.mjs (hashes). verify-site.mjs: leftover tikz-error or class metric, missing links, missing allowlisted files, fixture metric strings, og:image size. A TikZ miss that Hakyll swallowed dies here.

  7. Exit · pull request

    Build and verify only. No CNAME, no Pages artifact, no deploy.

  8. main · Pages

    Write _site/CNAME and .nojekyll. Upload artifact. deploy-pages@v4. On failure, sleep 30s and retry once.

  9. Browser · MathJax + mhchem

    Config, then MathJax 3.2.2. loader.load ['[tex]/mhchem']. Dollars off at this layer. Typesets body math and \ce{…}. Does not re-touch TikZ SVG.

  10. Browser · print

    window.print() or File → Print. Same HTML. Post / résumé / colophon each have their own @media print block. No .pdf is written to disk.
